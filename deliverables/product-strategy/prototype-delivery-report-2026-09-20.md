## 📌 TL;DR（执行摘要，3-5 行）

- **核心目标**：把「线框浏览工具」升级为**可点击、有反馈、能跨屏流转状态**的原型——点按钮真的会跳转，控件真的有响应，流程真的会改变系统状态。
- **关键决策**：不做「23 张灰图连热区」，而做**单文件产品外壳型原型**——有顶栏 / 全局搜索 / 通知 / 角色-作用域切换器 / 左侧导航，屏幕之间靠一个 202 个动作的动作表驱动，且带一个**真实的可变数据模型**（提交、队列、待办、审计、配置版本都会随操作增减）。
- **关键决策 2**：把 PRD 的硬约束做成**实现层的机制**而不是文案——L1 命令点不到、L4 无权限与不存在同措辞、L5 PA 只见元数据、L6 四维状态不合并、S03 缺项按钮禁用且点得动的只有「为什么不能点」。
- **验证结论**：460 次渲染（23 屏 × 4 角色 × 5 态）零错误；**零死按钮、零失效跳转**；6 条端到端流程 **44/44 检查通过**。
- **下一步**：产品负责人确认 5 项待裁决 → 用 6 条流程做一次 30 分钟评审 → 按高风险屏优先做高保真。

**这轮验证还抓出 3 个真实代码缺陷**（不是测试问题，是会在浏览器里真出错的）：

1. **键盘快捷键会崩** — 按 `R` / `M` 调用的动作假设有元素参数，从键盘触发时 `el` 为 undefined 直接抛错，抽屉打不开。已改为不依赖元素参数。
2. **三级弹层配色从未生效** — CSS 写的是 `.modal.s1/.s2/.s3`，代码生成的是 `'S01'.toLowerCase()` = `s01`，选择器永不命中。已改为显式映射 `S01→s1`。
3. **弹层 class 有多余空格** — `"modal " + "" + " s1"` 产生双空格，属潜在脆弱点，已改为拼接后取整。

> 这 3 个缺陷都不是靠肉眼看出来的 —— 是 mock-DOM 审计跑键盘分支时暴露的。**这就是为什么可交互原型必须做程序化审计**：界面上看起来都正常，只有点下去才知道。

## 2.6 追加的门禁项（来自两位成员的最后复核意见）

**（1）L1 扫描条件太弱 → 已换成结构化判定**（瑞思指出）
只搜「命令 / 忽略 / %」这些关键词不够 —— 最危险的形态是**命令被做成了一个可点块**，那种情况下文本命中但单看文本查不出来。已改为**结构化扫描**：对每个命中 token，检查它之前最近一次 `<` 到 token 之间是否出现 `data-act` / `data-nav` / `<button` / `<a ` —— 命中即判失败。并做了**反向自证**：用一个故意写坏的样本（`<button data-act="x">忽略以上所有规则</button>`）确认扫描器真的会报警，避免「扫描器永远说没事」。实测 4 个 token 在 23 屏里全部为纯文本。

**（2）L4 无权限检查 → 已升级为全遍历**（瑞思指出）
不再只看 1 个页面代表，而是 **23 屏 × deny/empty 两态全遍历**，逐项检查：对象标题是否泄漏（用 3 个真实条目标题当探针）、是否出现「隐藏了 N 条」、是否出现 `****` / 占位块、是否出现权限侧信道措辞。实测 **0 处泄漏**。

**（3）四维正交性口径 → 已补进界面**（竞析指出）
演示时最容易被问到「这四维会不会互相矛盾」。原设计虽写了「四维独立」，但没有正面回答这个问题，容易被理解成「互斥」。已在**四维图例弹层**里补一张判定表：

| 组合示例 | 是不是矛盾 | 应该怎么读 |
|---|---|---|
| 已发布 · 待验证 · 待复核 · 可检索 | **不矛盾（最常见）** | 刚发布、还没验证、该复核了 → 可正常引用，但别当确定结论 |
| 已发布 · 已验证 · 当前 · 可检索 | 不矛盾 | 健康态：可直接作为结论引用 |
| 已发布 · 已验证 · 已过时 · 可检索 | 不矛盾（需注意） | 结论当时对、环境已变 → 引用前先看失效条件 |
| 已撤回 · 已验证 · 当前 · 已暂停检索 | 不矛盾 | 正文不再返回；验证记录作为历史留痕保留 |

并统一口径为「**四维正交：可并存、不互斥、无所谓冲突**」。同一句话也写进了 KB-02 的组合横幅与 F1 流程引导条 —— 演示者照读即可，不必背台词。

## 2.7 第三轮：用户友好性复查（9 项摩擦点，全部修复）

用户要求「再检查一下操作是否对用户友好」。我没有预设结论，而是把原型当产品走了一遍真实用户路径，查出 **9 处摩擦**并全部修复：

| # | 摩擦点 | 为什么这是问题 | 修复 |
|---|--------|----------------|------|
| 1 | 页面跳转菜单**选完不关闭** | 点击后菜单一直盖在刚打开的内容上，用户必须再点一次空白处才能看内容 | 选中即关菜单 |
| 2 | toast **盖住演示引导条按钮** | 引导条在 `bottom:0`（高 70px），toast 在 `bottom:18px` 且 z-index 更高 → 演示时「上一步/继续」点不到 | 引导条出现时给 body 加 `guiding`，toast 自动抬高到 92px |
| 3 | 收起引导条后提示**指向不存在的入口** | 提示说「可在页面地图里重开」，但页面地图里根本没有这个按钮 —— 用户会去找一个不存在的东西，信任直接受损 | 页面地图底部补上「重开首屏引导条」；提示改为指向真实入口 |
| 4 | J/K 翻页会**连撞 5 屏权限墙** | 顺序遍历全部 23 屏，DEV 从 M3 末页按 J 会连续经过 M4/M5 的「该模块未向你授权」 | 翻页只在本角色可访问的屏幕间循环（实测连按 40 次 × 4 角色 = 160 次翻页，0 次撞墙） |
| 5 | 重置原型**不彻底** | 只重置了数据，角色/作用域/四态/热区/引导条/页签筛选全部残留 —— 用户以为回到了起点，其实没有 | 重置回到完整初始态（TL + ads/repo-1 + 正常 + 引导条显示 + 清空全部筛选） |
| 6 | 审核队列**想勾选却被跳走** | 复选框只有 13px 命中区，点在旁边落在整行的「进入审核」上 → 意图被劫持 | 勾选热区扩大到整个单元格（负 margin 撑满），内层 input 设 `pointer-events:none` |
| 7 | 弹层/抽屉打开时**背景仍能滚动** | 滚动穿透，视觉上很廉价，也容易误操作 | 打开时锁 `overflow`，关闭自动解锁 |
| 8 | 快捷键**只列字母不说是干什么的**；`H` 键行为诡异（只是改一行文字） | 用户没法知道按下去会发生什么 | 新增**帮助面板**（H 或「更多 → 怎么用」）：四个开关的作用、三个常驻面板、完整快捷键表（每个键都写作用）、三级防误操作图例；`H` 键改为打开它 |
| 9 | 控制条**塞了约 20 个控件、折行到两排** | 第一眼信息过载，重要的（身份/四态）被淹没 | 次要工具收进「更多 ▾」：顶层控件收敛到 **8 个，单排显示** |

**另一处非结构性但重要的问题**：`dismissIntro` 那句提示与「重置原型」的不彻底，都属于**原型对用户说谎**——它承诺了一个不存在的行为。这类问题的破坏力比功能缺失大，因为用户会开始怀疑其他提示。

> 本轮新增一套 **用户友好性专项检查（39 项断言）**，覆盖菜单闭合、层级遮挡、可发现性、可达性、状态残留、误点防护、滚动锁定、帮助自解释。现共 **9 套校验、共 351 项断言**。

## 2.8 第四轮：改造为传统后台管理布局与设计

用户要求「符合传统后台管理的布局和设计」。原型原来是**自定义现代布局**（浅色左导航 + 顶部工具条 + 自由卡片流），已整体改造为**传统后台范式**（Ant Design 4 一代的经典观感）。

### 2.8.1 布局层：从「自定义外壳」改为「经典后台外壳」

| 部件 | 改造前 | 改造后（传统后台范式） |
|------|--------|------------------------|
| 侧边导航 | 浅色 214px 平铺列表，模块名当分组标题 | **深色 #001529 侧边栏**，模块=可折叠分组（带图标 + 数量角标），页面=缩进子项，当前项蓝底高亮 + 右侧竖条；无权限模块灰显不可点 |
| 折叠 | 无 | 顶栏汉堡按钮，收起后 64px 只留图标；窗口 ≤1180px 自动收起 |
| 顶栏 | 品牌 + 假搜索框 + 通知 + 身份区 | **面包屑在顶栏**（可逐级回退）+ 搜索/通知/帮助图标 + 用户区（头像+姓名+角色 Tag+下拉菜单） |
| 页签栏 | 无 | **多页签导航（tags-view）**：打开过的页面自动生成页签，可切换、可关闭、关当前页签自动切到相邻页；重复打开不重复建页签 |
| 页面头 | 面包屑 + 标题 + 说明 + 操作（多行堆叠） | **标题左 · 操作右同一行**：标题 + 页面 ID 徽标 + 风险徽标，说明在下方，主操作固定右上 |
| 出口条 | 混在卡片流里 | 独立 `.exitbar` 横条，位置固定可预期 |

### 2.8.2 视觉层：切换到 Ant Design 4 设计令牌

| 令牌 | 旧值 | 新值（传统后台） |
|------|------|------------------|
| 主色 | #2B6CF6 | **#1890ff**（AntD 蓝） |
| 页面底色 | #F5F6F8 | **#F0F2F5** |
| 圆角 | 8px | **2px**（经典后台的方正感） |
| 基准字号 | 13px | **14px** |
| 控件高度 | 30px | **32px**（按钮 / 输入框统一） |
| 侧边栏 | #FFFFFF | **#001529** 深色 |
| 语义色 | 自定义冷暖色 | **#52c41a / #faad14 / #ff4d4f**（AntD 成功/警告/错误） |

配套组件按 AntD 规范重写：Tag 改浅底描边（`.chip`）、Alert 改浅底描边（`.banner`）、Card 带头部条（左标题右操作）、表格改密集风格（表头 `#FAFAFA`、行 hover 蓝色、操作列用蓝色文字按钮）、**Descriptions 风格 kv**（标签左 190px · 值右 · 行分隔线）、Steps 带圆形序号、Tabs 下划线式、Modal 改**顶部对齐**（80px 起，不再垂直居中）、Message 改**顶部居中**。

### 2.8.3 补的传统后台必备件

- **表格分页器**：原来只有一行文字说明，现在补了 AntD 风格分页（`‹ 1 2 3 ›` + `共 N 条` + `N 条/页`），接到 5 张主列表（我的提交 / 审核队列 / 审计日志 / 治理队列 / 用户与角色）；单页时自动不显示。分页按钮有真实响应（不是死按钮）。
- **用户下拉菜单**：头像 → 账号与身份（角色 / 作用域 / 授权范围 / 知识正文可见性）+ 一键切身份。
- **侧边栏图标集**：为 8 个模块画了内联 SVG 图标，收起态只显示图标。

### 2.8.4 本轮抓到的一个真 bug（之前所有轮次都漏掉了）

截图验收时发现**无权限页面把代码本身当文本渲染了出来**：

```
empty("🔒","该模块未向你授权","当前身份 领域负责人 TL（TL）看不到该模块的入口。…,"切换身份 切到 KM ")
```

根因：`render()` 里写的是 `vp.innerHTML = pageHead(s,'') + 'empty(' + JSON.stringify(...) + ')'` —— **拼了一个 `empty(...)` 字符串，却从来没有调用 `empty()`**。这个 bug 从原型第一版就在，历经三轮共 7 套校验都没发现。

**为什么漏了三轮**：之前的断言写的是 `/该模块未向你授权/.test(view())` —— 而这段文字在**字面量里也存在**，所以「拼出来的源码」也匹配通过。**断言匹配的是文本内容，没匹配「这段文本是不是被组件正确渲染出来的」。**

修复：改为真正调用 `empty()`，并补上 `exitBar()`（顺带修掉「角色级无权限页没有出口条」这个死角问题，它违反了瑞思清单第 4 项）。

**并新增第 9 套校验「渲染完整性」**，专门扫这类问题：对全部 460 次渲染，剔除 HTML 标签后检查可见文本里是否出现 `empty("` / `ACT("` / `sec("` / `tbl([` / `JSON.stringify(` / `undefined` / `[object Object]` / `NaN` / `+'`（断掉的拼接）。同时扫了 24 个组件函数名，确认没有同类残留。

> 这是本项目最有价值的一条经验：**「文本出现了」不等于「组件渲染了」**。断言必须能区分「正确的组件输出」和「源码被当文本输出」，否则会给出假阳性。

## 2.11 第七轮：角色授权矩阵与内容门禁（用户提问「我应该有一个角色看到所有的页面内容吧」）

### 2.11.1 审计出的三个真问题

| # | 问题 | 性质 |
|---|---|---|
| P1 | **平台管理员（PA）是可见面最窄的角色 —— 11/22，比一线开发者还少 1 屏**，且缺的正是它本职相关的页 | 授权错配 |
| P2 | **DEV 能进「冲突裁决队列」与「冲突裁决详情」，却进不了「治理队列」** —— 裁决要读两条相反结论才能判，权限要求高于治理队列。这是授权写反了 | 授权写错 |
| P3 | **M7 三屏规则不一致**：DEV 能进 CFG-02/03 却进不了 CFG-01；而「我的工作台」（M1）给全角色，「我的贡献」（M3）却排除 PA —— 两处同为「我的」却规则不同 | 规则不自洽 |

另有一处更严重的：**无权限模块在侧边栏渲染为灰色不可点的 `.locked` 项** —— 灰条与界面差异正是 L4 明令禁止的存在性侧信道。

### 2.11.2 定论：把「权限」拆成三层，而不是一层

用户问「应不应该有一个角色看到所有页面内容」。正确回答不是「加一个超管」，而是先把问题拆开：

| 层 | 问题 | 原则 |
|---|---|---|
| **入口可达性** | 能不能进这个模块/页面 | 按职责授予；**队列页可以给，详情页要谨慎** |
| **内容可见性** | 进去后能看多少字段 | 由 L4 / L5 独立控制，**与入口权限无关** |
| **操作可行性** | 能对它做什么 | 只给「做完能成功」的操作 |

第三层是本次新增的判据，也是解开矛盾的关键：**「能看见」不等于「能操作」，给了按钮但做不成事，就是死胡同。**

**最终结论：不新增第 5 个角色。** 把现有 PA 补成「平台管理该有的入口 + 内容仍受 L5 约束」即可。新增角色的代价是 5 × 22 = 110 格授权矩阵要长期维护，而收益与 PA 完全重叠。

### 2.11.3 修正后的授权矩阵（22 屏 × 4 角色）

可达数：**DEV 8 · TL 16 · KM 17 · PA 15**（原为 DEV 12 · TL 16 · KM 17 · **PA 11**）

| 变更 | 内容 | 依据 |
|---|---|---|
| ↑ PA 补「监督入口」 | 审核队列 / Lint 与治理队列 / 冲突裁决队列 / 共享范围变更审批 | 平台运行监督需要看到积压规模 |
| ↓ PA 收「详情入口」 | 审核详情 / 冲突裁决详情 | 详情必须读正文才能判，L5 禁止 → 给了就是死胡同 |
| ↓ PA 收 M3 | 我的提交 / 提交详情 / 我的反馈与验证记录 | **M3 是「知识生产者账本」，不是「跨模块聚合门户」**。PA 不提交候选、不提交验证（其页面内已明示「反馈必须来自实际使用者」），给它这三页是自相矛盾 |

| ↓ KB-04 差异折叠 | PA 可达，但版本差异默认折叠 | diff 会同时渲染新旧版正文 → 等于绕过正文权限 |

### 2.11.4 PA 监督视图（本轮主要新增实现）

给 PA 的队列页不是「详情页减字段」，而是一套独立的监督渲染：

- **策略声明块**（四问自解释）：为什么不可见 / 少了什么 / 为什么不能代处置 / 要看某一条怎么办
- **聚合卡片**：待审 3 · 已超时 1 · P0 占比 **1 / 3**（分子/分母，不是分数）· 平均等待 1.6 天（中位数 1.2 · 样本 3 条）
- **列白名单**：条目 ID / 版本 / 领域 / 类型 / 来源仓库 / 优先级 / 等待时长 / 状态 / 负责人
- **列黑名单（不渲染，不是打码）**：标题、增量断言、适用条件、争议点、建议动作、审核意见
- **无操作列**，页头也只留「刷新」

页头这处是特意补的：初版只在表格里禁了操作列，**页头仍留着「批量标记」「批准共享范围变更」** —— 等于把死胡同按钮留在了最显眼的位置。

### 2.11.5 导航：无权限模块不再出现

`.locked` 灰色锁定项全部移除，改为**按角色过滤菜单**（真实产品常态，也符合 L4「无权限 = 不存在」）。

「切换角色后界面是否真变了」的可核对证据，**不放产品 UI**，而放到顶部演示控制台的「更多 → 角色可见范围对照」：实时渲染 22 行 × 4 列矩阵，并标注「这是评审用的对照表，不是产品功能」。

原因：产品界面里若写「本角色可见 15 / 22 屏」，那个**总数本身就暴露了「存在你看不到的页面」**，属 §3.3 禁止的存在性侧信道；而且它属于演示说明，不该进产品 UI（这正是上一轮用户批评过的「元信息污染产品界面」）。

## 2.12 第八轮：全模块可达的「校对」能力（用户需求：「我需要一个无条件全模块可达的角色，这个角色目前只用于我校对每个页面的设计」）

### 2.12.1 先纠正一个会让校对失效的直觉

用户要的是「一个能到达所有页面的角色」。但团队独立分析后指出一个反直觉的事实：

> **单一全权视角是陷阱。** 它只渲染「最全的那一版」，于是**所有降级态被遮蔽** ——
> PA 的正文策略块、被过滤的导航项、被裁掉的操作列与按钮、L4 要求「不得出现」的占位……
> 你以为在核对 22 页，其实只核对了**同一个视角下的 22 页**，而设计的正确性恰恰藏在差异里。

于是「全可达」被实现为 **22 屏 × 角色视角**，而不是 22 屏 × 1 视角。这一点决定了整个方案。

### 2.12.2 交付了两个东西，用途严格分开

| 交付 | 是什么 | 用途 |
|---|---|---|
| **SA · 组织所有者**（第 5 个角色） | 无条件全模块可达（22/22），可读知识正文，读正文时页面常驻留痕条 | 看**设计全貌**：所有页面、所有字段的完整形态 |
| **校对模式**（评审脚手架开关） | 打开后可**用任一角色**到达全部 22 页，并在页面上标注「该角色并不持有本页入口，仅供校对版式」 | 逐页校对：**按角色**核对每页在该角色下的真实设计 |

**为什么两个都要做**：SA 满足用户原话（要一个角色）；校对模式满足用户目的（逐页校对）。只给 SA 会让校对漏掉降级态；只给校对模式则不满足「要一个角色」的字面诉求。二者互补，不能相互替代。

**校对模式的具体能力**（按团队分析定优先级）：
- 进度追踪：`第 N / 22 页` + 进度条 + `已核对 N / 22`
- 逐页结论标记：`✓ 通过` / `✎ 需修改` / `— 跳过` + 一格备注
- **跨角色差异提示**：对「同页多角色呈现不同内容」的页面（KB-02 / KB-04 / 4 个队列页），提示「本页在 N 个角色下不同」并给出一键切角色按钮
- **方法论护栏**：当当前角色是 SA 时，常驻提示「SA 是全貌视角，会遮蔽降级设计，请切 DEV/TL/KM/PA 逐个核对」
- 持久化：存 `localStorage`（22 页的校对会跨多次刷新），并在条上显示保存状态
- 导出：一键生成 Markdown 校对记录（逐页结论 + 备注 + 合计），可直接贴进评审纪要

### 2.12.3 L5 怎么处理才不自相矛盾

L5 原文约束的是**平台管理员**，禁止的是「**用系统管理权限换内容权限**」。因此：

| 角色 | 正文权 | 来源 |
|---|---|---|
| PA 平台管理员 | ✗ 默认不可见 | 处于 L5 的禁止范围 —— **本次改动不动它** |
| SA 组织所有者 | ✓ 可见 | 权限来自**数据主权**（组织对自有数据的持有权），不是系统管理权限 —— 不落入 L5 的禁止对象 |

并且 SA 读正文时页面常驻一条明示：「你以组织所有者身份查看正文 —— 权限来自数据主权（非系统管理权限），本次访问已记入审计。PA 不受此影响。」

**关键断言已锁进校验套件**：「SA 的存在未放宽 PA 的 L5」「校对模式不是解禁开关（开启后 PA 依然看不到正文）」。

### 2.12.4 本轮抓到的真 bug

**`visibleNav()` 有一份独立的角色过滤逻辑，没有走 `navAllowed`。**

后果：新增 SA 后 `navAllowed` 放行了，但**SA 的左侧菜单是空的** —— 页面能跳转、菜单里全没有。这是「同一规则有两处实现」的典型后果。

修法：让 `visibleNav()` 统一调 `navAllowed`，并在原地留注释说明曾因此出错。

### 2.12.5 校验

「权限矩阵与内容门禁」套件从 46 项扩到 **69 项**，新增：
- SA 无条件 22/22 可达；SA 是**唯一**全可达角色（3 个业务角色仍非全可达）
- SA 可读正文、有留痕条；PA 不受影响、不留痕条
- SA 在队列页看到正常列表（而非 PA 监督视图）
- 校对模式：默认关闭 / 跨角色可达 / **仍按当前角色渲染（降级态不被遮蔽）** / 不持有入口时有提示 / SA 全貌视角有护栏 / 标记与备注写入 / 重置原型不清校对记录 / 退出后回落

浏览器探针扩到 **97 项**（新增 sticky 堆叠未被校对条破坏、localStorage 落盘、跨角色渲染差异等真实 DOM 行为）。

累计：**十一套 / 459 项断言全部通过**。渲染审计 22 屏 × **5 角色** × 5 态 = 550 次，零错误。

### 2.12.6 留给产品负责人裁决

SA（组织所有者）目前是**「校对用的全权角色」**。若它将来要成为**真实产品角色**，需要补三件事：① 谁能获得该角色（授予流程）；② 读正文的审计事件定义（`req-` 命名）；③ 与 KM 的职责边界（SA 能读正文，是否也能改？当前设计是**不能改**，编辑仍走修订候选 + 审核）。

### 2.13.2 唯一一处「不能照做」：L1 删除的风险处置

用户要求删除「知识与指令的边界（L1 铁律）」并说「对项目没有任何作用」。这条约束（知识正文里的命令**不得**渲染成可点动作）是**安全约束**，删掉展示区块不等于删掉约束。

处置方式：**约束留在实现层，说明从界面上移除**：
1. 展示区块删除（满足用户）；
2. 命令类文本改由**真实内容**承载 —— 条目详情的「来源摘录」引用会话原文里的 `npm run deploy:prod`、`忽略以上所有规则`，按**纯文本**渲染、不带任何可点属性。这既是真实内容，也让 L1 的校验**有真实靶子、不会退化成空断言**；
3. 校对模式下在正文区显示一条「L1 守护中」提示，保证评审时仍看得到这条约束存在；
4. 校验套件保留 **DOM 级扫描**（文本命中 + 命中节点是 button/a/[onclick]/pointer 才算失败），另有**反向自证**（拿一个故意写坏的样本确认扫描器真会报警）。

> 这条经验值得记：删掉一个约束的展示载体时，**必须同时确认它的校验还有真实靶子**。否则「全绿」只是因为没东西可测。

### 2.14.2 两个通用机制（本轮主要产出）

**① 页面级操作的统一归位**

`pageHead(s, extra)` 改为 `pageHead(s)` —— **结构上就不接受按钮**（不是靠自觉不加）。页面级操作按两条路径落位：

| 路径 | 机制 | 适用 | 落位 |
|---|---|---|---|
| A | `sec()` 消费 `_pgActions` | 操作作用于**该页主对象**（导出、刷新、新建、批量标记） | 本次渲染的**第一个区块的区块头右侧**（AntD Card extra 范式） |
| B | `pgFoot(s)` 页底操作条 | 操作作用于**整页**（提交整份修订、批准发布、走完向导、保存授权） | 页面底部 sticky 条，与内容合并 |

判断「重复还是搬移」的规则：**与页内已有操作同任务 → 直接删**（不搬）。

按此删除了 7 处重复（KB-02 的 PA 预览与提交反馈、CONTRIB-02 与 FEED-01 的重置、CONTRIB-03 的两个操作、REVIEW-01 的筛选重置、IAM-03 的查询导出），并新增了 6 条页底操作条（KB-03 / REVIEW-02 / GOV-03 / GOV-04 / CFG-01 / CFG-03 / IAM-02）。

**② 设计标注机制（`.annot`）—— 比逐处删除更稳**

用户说「页面不做成说明项设计」。但有些内容**删了就丢了可验证性**（PRD 条款号、区块类型、页面职责、风险计数）。做法不是逐处删，而是**把它们收进一个类名，默认隐藏，仅校对模式显示**：

| 标注内容 | 为什么是「设计标注」 |
|---|---|
| 页面 ID（`UI-KB-03`） | 对使用者无意义 |
| 风险计数（`⚠ 2 项风险已就地缓解`） | 讲的是这个原型做了什么，不是产品做了什么 |
| 区块类型（`工具条` / `表单` / `列表`） | 产品界面不会标注「这是一张表」 |
| PRD 条款引用（`（§6.8.3）`） | 评审要能追依据，使用者不知道 § 是什么 |
| 页面职责描述 | 多页本身就是设计论证（如「筛选在表格上方」「替代手写规则」） |

实现：`.annot{display:none!important}` + `body.proofing .annot{display:inline-flex!important}`。43 处 PRD 条款号用**注释感知**的正则包裹（代码里的包裹，注释里的不动）。

**防呆（成员提出，已固化为断言）**：
- 字段级填写帮助 `.fh` **永远可见**，不得混进 `.annot` —— 它是给使用者的
- 系统行为提示（如「提交后进入审核，不会直接生效」）**永远可见**
- 看似像条款号的**文档章节号**（`组件文档 v1.2 §3`）属真实内容，**不包裹**

## 3. 「直观 / 好操作」在原型里的可点证据

瑞思（用户研究员）从用户视角产出的《可交互原型的交互验收标准》覆盖 8 个方面 + 交付前 20 项自查清单。下面逐条给出**在本原型里可以直接验的对应实现**：

### 3.1 「可点击」的定义（装饰 vs 可点要能一眼区分）

- **实现**：按 `W` 打开**热区高亮**——所有可点元素加橙色虚线框 + 右上角橙点；装饰元素（说明文字、指标卡脚注、L1 示例里的「命令」）无任何标记。
- **`本页风险与缓解` 抽屉里给了「本页可点热区清单」**，逐条列出本屏所有可点元素，共 N 处。
- 点不动的元素就是装饰，点了不会有任何反应 —— 这是刻意的。

### 3.2 死角：每屏至少 3 条出口
- **实现**：每屏底部固定**出口条**：`← 返回上一页` + `待办工作台` + 该屏 2–3 条语义出口（如详情页给「版本历史 / 反馈提交 / 回检索」）。
- 审计确认：23 屏全部 ≥3 条出口，无死角。

### 3.3 角色与作用域切换必须「四处同时变」
- **实现**：切换角色时 ① 左侧导航可见模块 ② 自动跳转到该角色落地页 ③ 页面内按钮可用性重算 ④ 顶部徽标与作用域更新 —— 并弹出 toast 明确告知这四项都变了。
- 实测：TL 切到 PA 后，M4/M5 变成「模块级不可见」，M7/M8 出现；KB-02 从「提交反馈」变成「以 KM 视角预览」。
- **作用域切换改的是数据，不是标签**：顶栏 `ads / billing` 分段器 + `切换上下文 ▾` 弹层，按 `domain + repo` 双重过滤。实测三种作用域给出**三种不同且都非空**的数据：`ads/repo-1` → 待办 4 / 队列 3；`ads/repo-2` → 待办 2 / 队列 1；`billing/repo-3` → 待办 3 / 队列 2。顶栏徽标、面包屑、列表条数与计数同步变化，仓库级切换还会显示「跨域仓库」提示。
- 作用域弹层里还有一条硬约束：**业务域必选、无默认值**，并校验仓库映射 —— 不许按名称猜权限（§8.3）。

### 3.4 四态演示
- **实现**：控制条上的**四态开关，默认停在「正常」**（等于关闭），视觉上与产品 chrome 明显区分（紫色系 vs 产品白/蓝）。
- 切态**不跳页**：当前屏原地变成骨架 / 空态 / 错误 / 无权限，不丢上下文。
- 错误态带 `request_id: 8f3a1c92`、可重试、并告知「普通编码可继续」；空态一律带下一步动作；无权限态用统一措辞且**不提供申请入口**。
- 瑞思建议「只做 3 个代表页」，本版做到 **23 屏各有自己的四态文案**（超出要求，无维护负担——文案来自规格书字段）。
