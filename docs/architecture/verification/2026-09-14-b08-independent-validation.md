# B08 合成使用反馈与独立验证记录

日期：2026-09-14。范围：固定合成 tenant、显式 loopback HTTP 与真实 PostgreSQL/Git/证据存储；不包含真实组织登录、宿主验收或生产资料。冻结 v2.0.0 契约及生成文件未修改，未增加依赖、提交代码、部署或迁移现有用户数据卷。

## 实现与规则

- 使用和反馈按主体/event_id 幂等，改变载荷冲突；客户端不能提交 retrieved、validation_submitted 或 validation_accepted。服务端在实际完成事务中记录这些事件；检索重传不重复记账。
- 验证提交按 event_id 和实际方法/结果/环境/证据指纹去重，绑定任务 owner、repo、环境与确切知识版本。返回 pending；提交 success 不晋升。权限和证据在存储 I/O 后再次核验，撤权则事务回滚。
- 独立审核拒绝自审，要求 validation-review 能力及相应内容/证据授权；接受前核验 retained 证据片段、hash、来源与有效期。CAS 与 operation_id 保留唯一决定及确切历史重传，审核历史只能追加。审核不改写 Git 正文。
- 一次 accepted targeted success 为 verified。proven 必须存在两组任务、提交者及证据内容均不同的证明；相同内容换证据 ID 不扩大独立性。repo 范围可在单项目达到 proven；非 repo 范围保守要求不同 repo。冻结契约没有结构化的适用项目分类，因此采用这一范围映射。
- 引用、使用、pending、失败、无结论及已识别的纯整体构建/测试方法不增加独立成功数。方法文本无法自动证明针对性；独立审核者负责确认方法、预期/实际结果、前提及例外适用于具体结论。
- 已登记权威镜像的组织确认可成为 verified，仍须独立批准及对应来源校验，不增加经验增量。旧正文版本的审核只更新该版本元数据；新正文从 draft 开始。
- accepted failure 标记 review_due、生成去重 counterevidence_review 任务，保留已有成功的成熟度与最后成功验证时间，不自动暂停服务。Worker 当前只执行发布和索引；反证任务交由人工及后续 B10 流程，更正通知尚未投递。
- 待审列表使用主体/授权版本/筛选/端点绑定的签名游标。证据不可读时整页失败关闭，不暴露待审正文。六个 MCP 工具已接 HTTP，ingest-knowledge/get-config 继续明确未就绪。

## 数据与安全

[007 迁移](../data/007_validation.sql)为加法迁移，新增指纹、事件绑定与强制 RLS 的独立审核历史；[008 权限](../../../ops/db/008_validation_grants.sql)只允许必要列更新，运行角色不能更新审核历史或正文。旧 accepted 数据没有 B08 证明绑定时不纳入重算，不自动追认。已有数据卷须由 owner 显式升级并配置角色。

证据在提交、审核、重传及重算时检查可用性；后台 TTL/撤权后的自动成熟度重算、磁盘删除及派生清理仍属于后续治理任务。本阶段没有实现 Web 审核表单、模型判定或任意方法的机器证明，也没有宣布 B01/B02、S0/S1 或 B10 完成。
