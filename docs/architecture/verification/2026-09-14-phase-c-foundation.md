# 阶段 C 基础：工程检查、数据库事务与授权

日期：2026-09-14。范围是进入人工知识闭环前的基础工作，不是 S1 业务闭环交付。

## 变更

- 恢复 `.github/workflows/ci.yml`。此前 `verify` 在格式检查时因 `.github` 不存在失败；没有通过删检查或忽略错误规避。CI 分别执行 verify、无网络 SQL 检查和真实 TCP 数据库套件。本轮没有提交、推送或触发远端 CI。
- API 统一数据库池工厂；新增内部 `withPrincipalTransaction`，参数化设置事务本地租户，校验主体 active/authz_version，业务和 commit 异常回滚，rollback 失败丢弃连接。可信主体必须来自认证边界，不得由请求字段决定。当前 HTTP 没有开放这个边界。
- PostgreSQL 授权服务按具体 capability 计算精确范围及显式祖先范围授权。repo 不获得父域/团队或兄弟仓库权限；管理能力不蕴含正文权限。无授权范围返回空集合，主体无效统一拒绝。无 ACL 缓存。
- 证据检查与知识读取权限独立，单条 SQL 复核主体、权限、每条证据的 ID/revision、available 和有效期；混合无权/不存在条目统一拒绝，不泄漏哪些条目存在。此方法检查证据记录可读性，不验证 locator 对应内容或对象 SHA；这些由 B03 存储复检实现。
- API 开发角色新增 repos/evidence 只读授权，无业务写入或身份 token 表权限。既有卷不自动变更，禁止删除卷或重跑 CREATE ROLE 脚本。
- 新增显式初始迁移执行器，仅合成本地目标；001/002 与 SHA-256 ledger 同事务执行，advisory lock 串行化，历史漂移拒绝。API 启动不执行迁移。现有未记录历史的库不自动接管；不提供破坏性 down migration、生产迁移或角色自动配置。
- 新数据库套件只使用随机本地端口临时容器，无主机数据挂载/持久卷；通过随机 guard 防止误把合成 fixtures 写入其他数据库。

普通 `pnpm verify` 明确跳过需临时数据库的套件；`pnpm test:database` 单独运行，不把 skipped 算作数据库验收。

真实 PostgreSQL 覆盖：初始迁移与重复执行、checksum 漂移、注入迁移失败的 DDL/ledger 回滚、两用户两仓库、显式域/团队范围、跨租户伪造、证据独立权限及精确 revision/可用性、撤权、禁用主体、旧 authz_version、单连接跨租户复用、事务提交/失败后的 RLS 和身份表拒绝。

授权范围计算只是后续领域服务的基础。正文/证据实际读取必须在同一事务内、带授权过滤完成，不得拿较早 allowedScopes 结果作为永久授权；后续发布也必须在激活时重新校验审批依赖和权限。当前并未实现这些业务读取/激活端点，测试不证明多人并发撤权、发布一致性或生产身份正确。
