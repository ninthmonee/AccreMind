### 关键技术方案（可复用，与线框那套 DSL 不同）
**「可变数据模型 + 动作表 + 事件委托」三角**：
- `M`（可变的业务数据：提交列表 / 审核队列 / 待办 / 审计 / 配置版本…）+ `S`（全局界面状态：屏幕 / 参数 / 角色 / 四态 / 开关）
- `SCREEN({id,name,mod,route,purpose,roles,risks,fixes,hot,states,exits,pact,render})` 注册屏幕；`render()` 返回 HTML 字符串
- `ACTIONS` 动作表 + **事件委托**（`data-act` / `data-nav` + `data-arg`）：避免重绑监听器，也让「按钮是否有响应」可被程序化审计
- 三条固定出口 `exitBar()`（返回上一页 / 待办工作台 / 语义出口）→ 结构上杜绝死角
- `screenBody()` 统一包装四态，所有屏 **只写一份 render**，四态靠 `S.view` 切换
- `modal() / confirmS(level,…) / whyBlocked()` 三级防误操作：S01 二次确认+必填理由+影响面+二次勾选；S02 影响面预览；**S03 不让点，点「禁用按钮」弹出的是「还缺这些」清单而不是报错**

### 踩坑与校验方法（重要，下次直接照做）
1. **审计要程序化，不能靠肉眼**。三件套：
   - `node --check` 抽 `<script>` 做语法门禁（本轮抓出 1 处 `kv()` 少一个 `)`)
   - **mock-DOM 全量渲染审计**：23 屏 × 4 角色 × 5 态 = 460 次渲染，正则扫 `data-act` / `data-nav` 与注册表比对 → **零死按钮、零失效跳转**（这比截图靠谱得多）
   - **流程仿真**：直接调 `ACTIONS.xxx` 模拟点击，断言跨屏状态变化（44/44 通过）
2. **mock DOM 必须实现 `querySelector`**，否则 `modal()` 的 `onMount` 里 `root.querySelector(...)` 返回 null 会崩 —— 手法：按 `#id` 或 `[data-act="x"]` 返回 store 里的桩元素，并给 `value/oninput/onchange`
3. **无头 Chrome 截图**：靠 `#ANCHOR`（`boot()` 读 `window.location.hash`）+ python 注入「`boot();` 后追加一行状态设置」，可批量产出任意「态」的截图，比手点快
4. 避免在 `<script>` 字符串里出现 `</script>`

**这轮还抓出 3 个真实代码缺陷（会在浏览器里真出错）：**
1. **键盘快捷键会崩**：按 `R`/`M` 的动作假设有 `el` 参数，键盘触发时 undefined → 抛错、抽屉打不开。修法：动作不要依赖元素参数，状态同步交给 `renderBar()`。

**教训**：断言会随结构调整而失效（把入口收进菜单后 2 条旧断言挂了）。**改结构时要同步更新断言，并补一条新断言防止入口被误删**（本轮补了「更多」菜单必须含 5 个入口 + 从菜单能真正打开）。

### ⚠️ 本轮抓到的一个真 bug（前三轮 7 套校验全部漏掉）
截图验收时发现**无权限页把代码当文本渲染出来**：`empty("🔒","该模块未向你授权",...)`
根因：`render()` 里是 `vp.innerHTML = pageHead(s,'') + 'empty(' + JSON.stringify(...) + ')'` —— **拼了 `empty(...)` 字符串却从没调用 `empty()`**。这个 bug 从第一版就在。
**为什么漏了三轮**：断言是 `/该模块未向你授权/.test(view())`，而这段文字在**字面量**里也存在 → 「拼出来的源码」也匹配通过。**断言匹配了文本内容，没匹配「这段文本是不是被组件正确渲染的」。**
修复：真正调用 `empty()` + 补 `exitBar()`（顺带修掉「角色级无权限页无出口条」的死角，违反瑞思清单第 4 项）。

### 新增第 9 套校验「渲染完整性」（11 项）
