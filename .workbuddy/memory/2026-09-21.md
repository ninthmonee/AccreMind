## 任务 3 第五轮：原型重构为 Ant Design 6 范式（用户要求）

用户要求：「用 Ant Design 6.x 的版本去重构，操作尽可能的简洁和直观，流程简易，交互友好，符合 Ant Design 哲学」。

### 关键判断
**AntD 6 相对 5.x 是视觉微调，真正跨代的是 v4 → v5/v6 那一跳。** 所以本轮实质 = 把原型从「v4 方正深色范式」整体迁移到「v5/v6 现代轻量范式」。

### 迁移手法（可复用）
**只重写 CSS + 外壳结构，23 个业务屏一行未改** —— 因为页面全部由组件函数（`sec`/`tbl`/`kv`/`chip`/`ban`）生成，改函数的输出样式即可 23 屏一起换装。前提是页面定义里不写裸样式。

### 设计令牌 v4 → v6（写入 CSS 顶部注释，可追溯）
`#1890ff→#1677ff` · `borderRadius 2px→6px`(SM4/LG8) · `colorBgLayout #F0F2F5→#f5f5f5` · `colorText .85→.88` ·
侧边栏 `深色#001529 通栏色块+白竖条` → `浅色#fff + #e6f4ff 圆角胶囊` ·
**多页签栏移除**（Pro 6 默认 `multiTab=false`）· 表格行 hover `蓝底→灰底#fafafa`（选中才蓝）·
卡片 `边框+阴影→极浅边框+无阴影+圆角8` · 阴影 `单层→三层叠加` · Modal `垂直居中→顶部对齐100px+遮罩高斯模糊` ·
Switch `36×20→44×22` · Segmented `边框+蓝填充→灰track+选中白底投影` · 间距 `随手→4/8/12/16/24 网格`

### 交互简化 8 项
控制台可折叠（〈按钮 + 点「原型」标签）· 控制台文案精简（长句收 title）· **移除多页签栏** ·
作用域按钮可区分（`ads/ads/billing` → `ads·1/ads·2/billing·3`）· **S02 中危改就地确认** ·
队列内「上一条/下一条」（审核/裁决连续处理）· 斜杠聚焦检索框 · 清理 `data-stop` 死属性

### ⚠️ 本轮抓到 5 个真 bug（前 2 个只有真实浏览器能发现）
1. **无权限页泄露队列条数**（侧信道）：`exitBar()` 无条件渲染队列导航，无权限页显示「1 / 3」= 告诉用户队列有 3 条，违反 L4。修复：无权限时只保留「返回上一页 / 回工作台」
2. **三层 sticky 全部失效**：①`.amain{overflow-x:hidden}` 使其成为滚动容器，内部 `.aheader/.ctxbar` 的 sticky 改为参照它；②`body{height:100%}` 把 body 锁在一屏高，使 `.pbar` 的 sticky 包含块不足。表现为**滚动时顶栏跟着页面滚走**。已在 CSS 留注释防改回
3. **S02 中危做成了弹层**：PRD §6.8 明确要求「就地区块警告」，弹层会遮挡上下文（用户无法对照「要排除哪个仓库」）。瑞思独立发现同一问题
4. **作用域按钮两个 "ads" 无法区分**（截图验收发现）
5. `data-stop` 死属性（委托里 `closest('[data-act]')` 取最内层 + `return` 已天然阻断冒泡）

### 新增两套验证（十套全绿，累计 278 项断言）
- **Ant Design 6 规范（61 项）**：把验收标准从 v4 换成 v6 + 9 条 v4 反模式检查。检查前先剥离 CSS 注释，否则会把「v4→v6 迁移对照说明」误判为残留
- **真实浏览器交互验证（46 项）**：headless Chrome 注入探针，验 mock 测不到的行为——事件冒泡、`document.activeElement`、真实插入节点、`getComputedStyle`、**滚动后的几何吸附（sticky）**、真实渲染文本无源码残留

### 教训
- **「mock 全绿」不等于「能跑」**：mock DOM 没有布局引擎、没有 CSS 计算、没有 focus、没有真实滚动。凡是「视觉/几何/浏览器行为」类断言，必须用真实浏览器
- **换设计系统时，验收标准本身要跟着换**：原「后台规范」套件的 8 项失败全是断言绑定了 v4 token 值（#1890ff / 2px / #F0F2F5 / #001529），属预期变化而非回归。测试断言若绑定具体设计值，重构时必须同步重写
- **断言要能区分「注释」与「实现」**：查残留色值前先剥离 CSS 注释
- **截图验收不可替代**：作用域按钮重名、页面头文字过载都是肉眼从截图发现的

## 任务 3 第七轮：角色授权矩阵与内容门禁（用户提问「我应该有一个角色看到所有的页面内容吧」）

### 审计发现的三个真问题
- **P1 授权错配**：平台管理员 PA 是可见面最窄的角色（**11/22，比 DEV 还少 1 屏**），缺的正是本职相关的页
- **P2 授权写反**：DEV 能进「冲突裁决队列/详情」，却进不了「治理队列」—— 裁决要读正文才能判，权限要求更高
- **P3 规则不自洽**：M7 三屏对 DEV 规则不一致；M1（给全角色）与 M3（排除 PA）同为「我的」却不同规则
- **另一处更严重**：无权限模块渲染为灰色 `.locked` 项 —— 灰条正是 L4 明令禁止的存在性侧信道

### 定论：把「权限」拆成三层（关键方法论）
| 层 | 问题 | 原则 |
|---|---|---|
| 入口可达性 | 能不能进 | 按职责；**队列页可给，详情页谨慎** |
| 内容可见性 | 能看多少字段 | 由 L4/L5 独立控制，**与入口权限无关** |
| 操作可行性 | 能对它做什么 | 只给「做完能成功」的操作 |

**第三层是解开矛盾的关键，也是本轮最重要的新判据**：给了按钮但做不成事 = 死胡同。
→ 所以 PA **进队列页（监督任务能完成）但不进详情页（必须读正文才能判）**。
→ PA 也不进 M3：M3 是「知识生产者账本」（PA 不提交候选/验证），不是「跨模块聚合门户」（M1 才是，后者人人有）。
   **这戳破了我自己的自相矛盾**：PA 页面里写着「提交反馈/验证 ✗ 反馈必须来自实际使用者」，却又给它「我的反馈与验证记录」页。

**结论：不新增第 5 个角色**（`析客` 判定）。代价 5×22=110 格矩阵长期维护，收益与 PA 完全重叠。

### 定稿矩阵（22 屏 × 4 角色）
可达数：**DEV 8 · TL 16 · KM 17 · PA 15**（原 DEV 12 · TL 16 · KM 17 · **PA 11**）
- ↑ PA 补监督入口：审核队列 / 治理队列 / 冲突裁决队列 / 共享范围变更审批
- ↓ PA 收详情入口：审核详情 / 冲突裁决详情（死胡同）
- ↓ PA 收 M3 三屏；↓ DEV 收 M5 全部；→ M7 三屏收敛为只归 PA；↓ KB-04 差异对 PA 默认折叠（diff 会渲染新旧正文）

### 主要新增实现
1. **PA 监督视图**（`paSupervise()` 通用组件 + 4 个队列页分支）：策略声明块（四问自解释）+ 聚合卡（比率带分子/分母）+ **列白名单** + 无操作列
2. **页头也要收敛**：初版只在表格禁操作列，页头仍留「批量标记」「批准共享范围变更」→ 补 `effPact()`，PA 在监督页只留「刷新」
3. **导航按角色过滤**：移除 `.locked`；角色差异证据移到脚手架「更多 → 角色可见范围对照」（实时 22×4 矩阵）
4. **计数信息不入产品 UI**：顶栏不写「可见 15/22 屏」—— 总数本身就暴露「存在你看不到的页面」

## 任务 3 第八轮：全模块可达的「校对」能力

用户需求：「我需要一个无条件全模块可达的角色，这个角色目前只用于我校对每个页面的设计是否正确」

### 关键洞察（成员独立分析给出，反直觉但正确）
> **单一全权视角是陷阱。** 它只渲染「最全的那一版」，把**所有降级态都遮蔽**——PA 的正文策略块、被过滤的导航、被裁的操作列、L4 要求「不得出现」的占位。
> 你以为在核对 22 页，其实只核对了**同一个视角下的 22 页**，而设计正确性恰恰藏在差异里。

→ 所以「全可达」必须实现为 **22 屏 × 角色视角**，而不是 22 屏 × 1 视角。

### 交付两个东西，用途严格分开
| 交付 | 是什么 | 用途 |
|---|---|---|
| **SA · 组织所有者**（第 5 角色） | 无条件 22/22 可达 + 可读正文 + 读正文常驻留痕条 | 看**设计全貌** |
| **校对模式**（脚手架开关） | 用**任一角色**到达全部 22 页，并标注「该角色并不持有本页入口，仅供校对版式」 | 逐页**按角色**校对 |

只给 SA 会漏降级态；只给校对模式则不满足「要一个角色」的字面诉求。二者互补。

校对模式能力：进度（第 N/22 + 进度条 + 已核对）+ 三种结论标记（✓通过/✎需修改/—跳过）+ 备注 + **跨角色差异提示与一键切角色** + **SA 全貌视角的「会遮蔽降级设计」护栏** + localStorage 持久化 + 导出 Markdown 校对记录。

### L5 的处理（关键表述，可复用）
L5 约束对象是**平台管理员**，禁止「用系统管理权限换内容权限」。
- PA：正文默认不可见（**本次未动**）
- SA：正文可见，权限来自**数据主权**（非系统管理权限）→ 不落入 L5 禁止对象；读正文常驻审计留痕

已锁断言：「SA 的存在未放宽 PA 的 L5」「校对模式不是解禁开关」。

### ⚠️ 本轮真 bug
**`visibleNav()` 有一份独立的角色过滤逻辑，没走 `navAllowed`** → 新增 SA 后 navAllowed 放行了，但 **SA 的左侧菜单是空的**（页面能跳转、菜单里全没有）。
→ 教训：**同一规则有两处实现，必然在扩展时漏改一处。** 已统一并留注释。

另：新插入的 `body.proofing .toastwrap` 规则被旧断言的正则先命中，造成 proto_ux 假失败——断言取 CSS 时应锚定完整选择器（`.toastwrap{position:fixed`）。

### 校验
权限套件 46 → **69 项**（SA + 校对模式全量）；浏览器探针 73 → **97 项**。
累计 **十一套 / 459 项断言全部通过**；渲染审计 22 屏 × **5 角色** × 5 态 = 550 次零错误。
交付物：`prototype-ai-knowledge-base-2026-09-20.html` 359 KB / 5,182 行 / 22 屏 / 231 动作

SA 目前是「校对用全权角色」。若成为真实产品角色，需补：① 授予流程；② 读正文的审计事件定义；③ 与 KM 的职责边界（SA 能读，**不能改**——编辑仍走修订候选+审核）。
